# 需求规格说明书 — trip_agent 智能旅行助手

> 状态:定稿 · 最后更新:2026-10-27
> 依据:`raw/业务需求文档-v0.md` + 《澄清问题清单》24 条问答记录 + §9 RP-1~RP-6 评审决议 + 2026-10-27 评审裁决(9 项)

---

## 1. 产品定位

为**自由行年轻人**和**家庭出游用户**提供个性化旅行规划:根据出发地、目的地、日期、预算与偏好,自动生成包含交通、住宿、景点、餐饮、预算、地图路线的完整行程计划,并支持导出。

## 2. MVP 基准场景

> **"我国庆节想从杭州去新疆玩 7 天,2 大 1 小,人均预算 8000 元,喜欢自然风光和美食,帮我规划完整行程。"**

所有验收标准围绕该场景的可执行变体编写。

## 3. 输入规格

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| 出发地 | 城市 | 是 | MVP 仅支持国内城市;允许与目的地相同,按本地游处理(不生成大交通推荐,住宿推荐改为可选) |
| 目的地 | 城市/地区/国家 | 是 | 支持省份级(如"新疆")与国家级(如"泰国")输入;出境目的地 MVP 阶段提示"出境游二期上线",不生成行程(见 §7 第 7 条);无法识别的输入(错别字/不存在的地名)自动纠错并请用户确认,无法推测时拒绝生成(AC-20) |
| 出行日期 | 起止日期或出发日+天数 | 是 | 禁止过去日期;远期日期不设限(天气按 F7 历史同期参考、票价按 AC-11 降级标注);天数不设硬上限 |
| 人数 | 成人数 + 儿童数 + 老人数 | 是(成人)/否(儿童老人) | 儿童老人影响行程密度与住宿推荐;总人数(成人+儿童+老人)≤ 9,超出拒绝生成并提示(AC-20) |
| 预算金额 | 总预算 或 人均预算(任填其一或同填,自动换算) | 否 | "人均"指每人全程所有分类合计;儿童按 0.5 个成人计入预算人数(预算人数=成人+老人+0.5×儿童);金额必须 > 0(AC-20);同填且换算不一致时以人均预算为准;未填金额时按所选档位生成并展示档位估算参考预算(F16),不做超支判定 |
| 消费档位 | 单选:穷游/舒适/豪华 | 否 | 消费偏好而非金额,默认"舒适";资源映射见 §4 档位映射表;F5 超支判定不受影响(仍按金额) |
| 偏好 | 标签多选 + 自由文本 | 否 | 标签:自然风光/历史文化/美食/小众秘境/亲子/摄影;自由文本不限长度(MVP) |

## 4. 功能清单与优先级

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F1 | 行程规划生成 | **P0** | 按天组织,每天分上午/下午/晚上三块,每块 1-2 个活动;含景点、餐饮(片区+品类+代表店,代表店附口碑摘要:评分/人均+好评差评要点,§7 第 5 条)、住宿推荐;**住宿推荐附 RollingGo 预订跳转链接**(官方渠道完成预订,见 §9 RP-2 补充决议) |
| F2 | 大交通方案推荐 | **P0** | 出发地→目的地往返:飞机/高铁/自驾三方对比(价格、耗时);**机票实时价格、火车票时刻/余票/票价经飞常准 MCP 实时查询**(决议见 §9 RP-1);**自驾方案里程/耗时来自高德驾车路径规划 API,费用(油费+过路费)为估算并按 AC-10 标注**(AC-24,补回原始需求"汽车/开车"要素);只查询不预订,附官方渠道跳转链接与「一键复制行程要素」(日期+航线/车次查询条件,见 §9 RP-2);**无直达方式(如无高铁/直飞)时自动提供中转组合方案**(AC-23) |
| F3 | 当地交通规划 | **P0** | 每日出行方式建议(包车/公交/打车/步行)及段间衔接;段间距离/耗时必须来自路径规划 API(§6 当地交通数据源,AC-21),经验性建议(包车行情/景区区间车)来自知识库+搜索校验 |
| F4 | 预算统计 | **P0** | 分类汇总:大交通/住宿/餐饮/门票/当地交通;总计与人均;超支判定见 F5;**必须经 calculator 工具计算**(§7 第 6 条) |
| F16 | 档位估算参考 | **P0** | 用户未填预算金额时,按所选消费档位生成行程,预算表用真实查询数据(房价/票价/人均餐饮)算出参考金额并**标注"档位估算参考"**,不做超支判定;有金额时正常走 F5 |
| F5 | 预算超支处理 | **P0** | **前置可行性校验**:预算 < 硬成本下限时拒绝生成,给出最低可行参考预算与调整建议(AC-17);硬成本下限 = 往返大交通最低价(飞常准)+ 最低价住宿 ×(天数−1)晚(RollingGo)+ 生存线餐饮 × 天数(= 按目的地实时查询的最低价餐饮)+ 最低当地交通(按高德路径规划与知识库行情估算,按 AC-10 标注),经 calculator 计算;门票不计入下限(用户可全程选择免费景点)。预算 ≥ 下限时:实际总成本超出预算上限 >15% 时必须给出 2-3 个降级方案(换酒店档位/减少付费景点等,AC-4);节余 >15% 时正常展示方案并给**非阻断升级提示**("预算充裕,可升级住宿档位"),用户确认后给出 2-3 个升级方案(AC-18);预算上限:输入总预算时即总预算,输入人均时 = 人均 × 预算人数(预算人数=成人+老人+0.5×儿童);**超支判定仅在用户提供预算金额时启用** |
| F6 | 地图标注与路线 | **P0** | 高德地图:每日景点 POI 标注 + 当日游览路线绘制,按天分图层 |
| F7 | 天气信息 | **P0** | 和风天气;出行日期超出预报范围时给历史同期气候参考,**UI 必须区分标注"实时预报/历史参考"** |
| F8 | 注意事项 | **P0** | 当地风俗禁忌、必备物品清单(结合目的地与季节);**数据源为三层结构(§6 注意事项数据源)**;涉及宗教/民族风俗的目的地(如新疆、穆斯林国家)必须输出对应禁忌条目(AC-15) |
| F9 | 异步生成+进度 | **P0** | 流式展示生成阶段("正在查询天气…正在规划路线…"),生成耗时 ≤ 90 秒(P90,AC-19) |
| F10 | 行程保存与回看 | **P0** | 免登录;生成即持久化并给唯一链接可回看;链接 MVP 永久有效,架构预留有效期字段 |
| F11 | PDF/图片导出 | **P1** | 行程单导出 PDF 与长图 |
| F12 | 行程节点编辑 | P2(二期) | 增删改景点并联动地图与预算——技术复杂度高,二期专项设计 |
| F13 | 用户系统 | P2(二期) | 注册登录、历史行程、多设备同步 |
| F14 | 联盟分销链接 | P2(二期) | 携程/飞猪 CPS 联盟跳转,用户去官方完成预订,平台赚佣金;决议见 §9 RP-2。**酒店跳转链接除外:随 MVP 由 RollingGo bookingUrl 直接带出**(见 §9 RP-2 补充决议) |
| F15 | 降价提醒 | P2(二期) | 机票:基于飞常准 MCP 定时监控票价,低于阈值推送(决议见 §9 RP-2);**酒店:基于 RollingGo 定时查价监控**(官方支持盯价能力),同房型降价推送 |

**消费档位资源映射表**(F16/Agent 推荐参数,定性标准,与目的地物价无关):

| 分类 | 穷游 | 舒适(默认) | 豪华 |
|---|---|---|---|
| 住宿 | 青旅/2-3 星 | 3-4 星/口碑民宿 | 5 星/度假酒店 |

| 当地交通 | 公交/拼车 | 打车/包车分摊 | 包车/专车 |

## 5. 验收标准(可执行形式)

**AC-1(行程结构)** 给定输入"杭州→新疆、10月1日出发7天、2大1小、人均8000元、偏好自然风光+美食",当用户提交后,则系统返回:7 天行程,每天含上午/下午/晚上三块,每块 1-2 个活动;行程必须同时包含五类推荐:**大交通出行推荐**(往返方案对比)、**当地交通出行推荐**(每日出行方式与段间衔接)、**住宿推荐**、**餐饮推荐**(片区+品类+代表店+口碑摘要)、**景点推荐**。(生成耗时验收见 AC-19)

**AC-2(儿童适配)** 给定输入含儿童或老人,当生成行程时,则每日付费/高强度景点 ≤ 2 个,且行程说明中包含节奏提示。其中"高强度"由 LLM 在生成时为景点打标(徒步/登山/高海拔/长时游览等)并以结构化字段输出,验收时按标签计数。

**AC-3(预算完整性)** 给定任意有效输入,当行程生成完成,则预算表包含大交通/住宿/餐饮/门票/当地交通五个分类、总计与人均金额,且各分类之和 = 总计。

**AC-4(超支降级)** 给定预算 ≥ 硬成本下限、但低于行程成本的输入(如新疆7天人均2000元),当实际总成本超出预算上限的比例 > 15% 时(恰好 15% 不触发),则响应中必须包含 2-3 个(≥2 且 ≤3)具体降级方案及其节省金额(calculator 计算)。

**AC-17(预算可行性下限)** 给定预算低于硬成本下限的输入(如新疆7天3成人、人均200元——低于往返大交通最低价;下限构成见 F5),当用户提交后,则系统**不生成行程**,返回:不可行说明(含硬成本下限构成明细)、最低可行参考预算(飞常准/RollingGo 实时查询数据经 calculator 计算,并按 AC-11/AC-12 标注查询时间)、调整建议(提高预算/缩短天数/更换近距离目的地);不得强行生成一份无法执行的行程。

**AC-5(地图)** 给定已生成的行程,当用户查看地图页,则地图上按天分图层标注全部景点 POI,并绘制当日游览路线;POI 坐标来自高德 API 而非 LLM 编造。

**AC-6(天气标注)** 给定出行日期超出天气预报范围,当展示天气信息时,则标注为"历史同期参考"而非"预报"。

**AC-7(异步进度)** 给定用户提交生成请求,当后端处理中,则前端实时展示当前阶段进度(至少 3 个阶段),提交后 3 秒内出现首个进度阶段,全程无白屏。

**AC-8(保存回看)** 给定已生成的行程(生成即持久化,无需显式保存动作),当用户在新浏览器打开回看链接,则看到完整行程内容——完整 = 五类推荐(大交通/当地交通/住宿/餐饮/景点)+ 预算表 + 注意事项 + 天气 + 地图标注,无需登录。

**AC-9(导出)** 给定已生成的行程,当用户点击导出,则获得包含完整行程单与预算表的 PDF 与长图两种格式(P1,可在 M4 后期交付)。

**AC-10(数据来源诚实)** 给定行程中任何价格信息,当其为估算值时,则 UI 标注"估算仅供参考"并区分于实时查询数据。

**AC-11(实时票务数据)** 给定行程含大交通方案,当飞常准 MCP 可用时,则机票价格与火车票余票/票价为实时查询结果并标注查询时间;当查询失败时,则降级为价格区间估算并按 AC-10 标注,不得静默展示估算冒充实时数据;远期日期无实时数据视同查询失败,同样降级标注。

**AC-12(实时酒店数据)** 给定行程含住宿推荐,当 RollingGo MCP 可用时,则酒店价格为实时查询结果并标注查询时间;当查询失败时,则降级为价格区间估算并按 AC-10 标注,不得静默展示估算冒充实时数据。

**AC-13(档位映射)** 给定用户选择"穷游"档,当生成行程时,则住宿推荐均为青旅/≤3 星,大交通不含商务舱/一等座;"豪华"档则住宿均为 5 星、当地交通含包车/专车。

**AC-14(档位估算参考)** 给定用户仅选择消费档位、未填写预算金额,当行程生成完成,则预算表完整展示五分类参考金额(由真实查询数据经 calculator 计算),整体标注"档位估算参考",且不出现超支判定与降级方案。

**AC-15(风俗禁忌覆盖)** 给定目的地存在显著宗教/民族风俗(如新疆、穆斯林国家),当生成行程时,则注意事项必须包含对应风俗禁忌条目(如清真饮食、着装要求、宗教场所礼仪);涉时效信息(签证/管制/预约政策)必须标注来源与查询日期,不得只给无来源的陈述。本版以示例目的地(如新疆)为测试基准,不维护完整触发清单。

**AC-16(餐饮口碑摘要)** 给定行程中的代表店推荐,当展示餐饮推荐时,则每家代表店包含:高德实时评分与人均消费、好评要点与差评要点各 ≥1 条(由搜索工具/知识库内容经 LLM 总结),并标注数据来源与时间;搜索无有效信息时如实标注"暂无足够口碑数据",不得编造评价。

**AC-18(预算充裕升级方案)** 给定实际总成本低于预算上限 15% 以上(节余 >15%)的输入,当行程生成完成,则响应正常展示方案,并包含非阻断升级提示(如"预算充裕,可升级住宿档位,是否浏览升级方案");用户确认后,系统给出 2-3 个升级方案及其增量金额(calculator 计算);用户不确认时不阻塞任何流程。

**AC-19(生成耗时)** 给定基准场景的可执行变体,当统计 20 次完整生成的端到端耗时,则 P90 ≤ 90 秒。

**AC-20(输入合法性)** 给定以下非法输入:总人数 > 9、预算金额 ≤ 0、出发日期为过去时间,当用户提交,则系统拒绝生成并给出具体原因提示;给定无法识别的目的地,当用户提交,则系统自动纠错并请求用户确认,无法推测时拒绝生成。

**AC-21(当地交通数据来源)** 给定已生成的行程,当检查当地交通的段间距离/耗时,则其必须可追溯至高德(国内)路径规划 API 返回(国外二期为 Mapbox),不得为 LLM 编造。

**AC-22(跳转链接与复制要素)** 给定已生成的行程,当查看住宿推荐,则每家酒店附 RollingGo bookingUrl 预订跳转链接;当查看大交通方案,则附官方渠道跳转链接(机票:携程/飞猪搜索页或航司官网;火车票:12306 引导)与「一键复制行程要素」入口。

**AC-23(无直达交通中转)** 给定无高铁直达或无直飞航班的出发地—目的地组合,当生成大交通方案,则必须提供至少 1 个中转组合方案,不得留空或省略该方式的说明。

**AC-24(自驾方案)** 给定任意出发地—目的地组合(出发地=目的地的本地游除外),当生成大交通方案,则除飞机/高铁外必须包含自驾对比方案:里程与耗时来自高德驾车路径规划 API,费用(油费+过路费)为估算并按 AC-10 标注。

## 6. 非功能需求

| 项 | 指标 |
|---|---|
| 规模 | MVP 自用+种子用户 < 100 人,不做水平扩容;关键参数(模型名/阈值/开关)走配置,不硬编码 |
| 生成耗时 | 完整行程 ≤ 90 秒(P90,AC-19),流式进度 |
| 成本 | 运营成本有限 → 架构必须含:LLM 调用缓存、按任务复杂度分层选模型、token 用量统计;单次生成成本 MVP 阶段只统计不设限(M6 固化成本目标) |
| 前端 | Next.js + TypeScript,**移动优先**响应式 |
| 地图 | 国内:高德 Web API(用户已有开放平台账号);**二期出境游:Mapbox(免费额度大、不绑卡、大陆可直连)+ OSM 兜底**(决议见 §9 RP-4) |
| 票务数据源 | 飞常准飞友 AI 开放平台(MCP 协议,按调用计费 0.05–0.5 元/次;Amadeus 作为国际线备选) |
| 内容数据源 | 搜索 API(国内博查/国际 Exa·Tavily)+ POI API(高德/Google Places)双链路;小红书半自动知识库(开发期采集+人工审核,决议见 §9 RP-5) |
| 酒店数据源 | RollingGo 酒店 MCP(道旅 DIDA,全球 200 万+ 酒店,实时价格/库存,2026-10-22 实测可用;LiteAPI/Amadeus 为国际备选;决议见 §9 RP-6) |
| 当地交通数据源 | 双层结构:高德(国内)/Mapbox(国外)路径规划 API 提供段间方式/距离/耗时(结构化,非 LLM 编造,AC-21);包车行情、景区区间车等经验信息来自小红书知识库+搜索 API 校验;LLM 常识兜底 |
| 门票数据源 | LLM 知识给价格区间 + 搜索工具校验时效性(价格/开放状态/预约政策),按 AC-10 标注估算;国内无门票类个人开放 API(美团/携程门票均无接口);国外二期候选 Klook/Tiqets(实时价格库存,但为合作伙伴审批制) |
| 注意事项数据源 | 三层结构:①文化风俗禁忌等**稳定知识**由 LLM 主答(训练数据覆盖充分,如宗教禁忌/民族风俗);②签证/管制/景区公告等**时效信息**由搜索工具校验,**官方源优先**(领事服务网、文旅部门公告);③小红书知识库补充真实旅行者经验(如"新疆夜市有巡逻,安全");时效性条目必须标注来源与查询日期 |
| 可用性 | LLM 超时/限流经指数退避重试(≤2 次)后仍失败时:展示已完成的部分结果、明示缺失部分并提供重试入口,不得直接报错给用户;超时阈值在 M1 ADR 冻结 |

## 7. 明确约束与排除项(MVP 不做)

1. **不做票务预订与支付**:实时**查询**经飞常准 MCP 提供(机票实时价格、火车票时刻/余票/票价,见 §9 RP-1);预订/支付跳转官方渠道(航司官网、12306、携程),不在站内完成。爬虫抓取方案经调研明确排除(合规与刑事风险)。
2. **不做行程编辑联动**(F12,二期)。
3. **不做用户登录**(F13,二期)。
4. **不做小时级排期**(精确到上午/下午/晚上);原始需求所述"精确程度可调节"特性留二期。
5. 餐饮推荐保持"片区+品类+代表店"级别;**代表店附口碑摘要**:评分/人均消费来自高德 POI 实时查询(国内),好评/差评要点由搜索工具+小红书知识库经 LLM 总结并**标注来源与时间**;不接平台评论直连(大众点评无合规 API);国外二期用 Google Places 真实评论(评分+评论文本,M1 核实绑卡门槛);运行时禁止实时爬取第三方平台(RP-5)。
6. **预算计算必须经 calculator 工具(tools/ 层,纯代码精确运算)完成分类加总/总计/人均/超支判定,禁止 LLM 心算加总**;Agent 只负责收集各项价格参数并组装为结构化预算对象(Pydantic 校验),AC-3"各分类之和=总计"由代码保证;降级方案的节省金额与升级方案的增量金额同样由 calculator 计算。
7. **不做出境游行程生成**(二期):目的地输入框接受国家级(如"泰国"),但出境目的地 MVP 仅提示"出境游二期上线";国外地图(Mapbox,RP-4)、国际机票(Amadeus,RP-1 备选)、签证/汇率等出境注意事项均维持二期。
8. **不做购物/特产推荐**:原始需求"必玩必买必吃"中的"必买"(购物/特产)MVP 不纳入,二期评估。

### RP-2:票务预订与支付能否作为二期工程?

- **提出**:2026-10-21,用户
- **状态**:✅ 已决议(2026-10-21 用户确认)

**评估结论(2026-10-21)**:

1. **核心障碍是资质与合规,非开发量**:
   - 机票出票需 GDS/代理人资质或航司 NDC 对接资质,个人不可得
   - 12306 明确禁止第三方代购,无官方接口;代下单属违规路径
   - 在线收款需企业营业执照(微信/支付宝商户号);经营旅游产品受《在线旅游经营服务管理暂行规定》约束(保证金、平台责任、投诉处理)
   - 收钱即承担出票失败、退改签纠纷、航变通知等售后责任,需客服体系
2. **纯工程量(假设资质齐备)**:订单状态机(10+ 状态)、支付对账、异步出票回调、各航司各舱位退改签规则引擎、航变通知、发票,参考行业经验为 3–5 名工程师 3–6 个月,与 MVP 总体量不成比例
3. **投入产出比低**:用户在携程/航司官网的预订体验已成熟,站内预订增量价值有限而资金/售后风险全由己方承担

**决议建议**:站内预订与支付**不纳入任何阶段**。二期替代方案:
- **联盟分销链接**(携程/飞猪联盟 CPS,个人可申请):带追踪跳转,用户去官方完成预订,平台赚佣金,零售后责任
- **降价提醒**(推荐,与现有架构契合):基于飞常准 MCP 定时监控票价,低于阈值推送,工程量约 1–2 周
- **一键复制行程要素**:格式化输出"日期+航线"查询条件,粘贴至 OTA/12306 直接搜索

**决议(2026-10-21)**:用户确认。站内预订与支付不纳入任何阶段;替代方案登记为二期候选功能:F14 联盟分销链接(携程/飞猪 CPS 跳转)、F15 降价提醒(基于飞常准 MCP 票价监控),均为 P2,优先级二期再定;"一键复制行程要素"作为 F2 的低成本体验补充,随 MVP 实现。

**补充决议(2026-10-22,用户确认)**:"跳转官方渠道"分层落地:

| 类目 | 跳转目标 | 链接来源 | 阶段 |
|---|---|---|---|
| 酒店 | RollingGo 预订页 | searchHotels 返回的 bookingUrl(自带日期/人数参数与返佣追踪,RollingGo 支持开发者返佣) | **随 MVP 带出**(F1 住宿推荐附带) |
| 机票 | 携程/飞猪搜索页、航司官网 | 按"出发地+目的地+日期"拼搜索链接 + "一键复制行程要素" | MVP(链接)/P2(联盟 CPS) |
| 火车票 | 12306 | 不支持带参数深链,引导 + 复制要素(车次/日期) | MVP |
| 景点门票 | 携程/飞猪/景区官方 | 联盟链接或搜索链接 | P2(随 F14) |

跳转方案无资质与合规问题(交易与售后均在官方平台);RollingGo bookingUrl 为零额外成本的现成字段,故酒店跳转提前至 MVP,F14 其余部分维持 P2。

### RP-3:地图平台选型——国内/国外分别用什么?个人开发者免费额度如何?

- **提出**:2026-10-21,用户
- **状态**:✅ 已决议(2026-10-21 用户确认)

**调研结论(全网调研,2026-10-21)**:

1. **国内(法定只能用国内图商)**:中国境内发布地图须由持测绘资质单位提供(需审图号),且坐标系为 GCJ-02(与 GPS 的 WGS-84 存在偏移,跨国数据混用需转换)。Google Maps 在国内无审图号且服务不可达,不可选。三家对比(个人开发者免费配额):
   - **高德**(用户已有账号):个人认证后 JS 地图初始化 150 万次/月、驾车路径规划 15 万次/月(QPS 3)、关键字搜索 **5,000 次/月(偏紧)**、天气 5,000 次/月;未认证配额为 0;超量 30 元/万次;商用放量需企业认证
   - **腾讯位置服务**:个人开发者各接口统一 1 万次/**日**(≈30 万次/月,QPS 5),搜索类同样 1 万次/日,个人档最宽松
   - **百度**:个人档地点检索仅 100 次/日、逆地理 300 次/日,明显偏低
2. **国外(二期出境游场景)**:
   - **Mapbox**:免费档 5 万次/月地图加载 + 10 万次/月地理编码 + 10 万次/月路径规划,样式自定义强,海外中文 POI 一般
   - **Leaflet + OpenStreetMap/MapLibre**:完全免费无 Key;但公共瓦片与 Nominatim 地理编码有严格使用策略(1 次/秒、禁止批量、必须署名),商用/放量需自建或买托管瓦片(MapTiler 等)
   - **Google Maps Platform**:数据质量最好但最贵;2025-03 起改为按 SKU 免费额度(约 1 万次/月),需绑信用卡,超量价格高
3. **调试期结论**:高德个人认证账号的免费额度(JS 150 万次/月、路径规划 15 万次/月)对开发调试和 <100 用户的 MVP **完全够用,零成本**;唯一注意点是关键字搜索 5,000 次/月偏紧,必须做 POI 结果缓存(同一景点只查一次),必要时以腾讯位置服务(1 万次/日)作搜索补充。

**建议**:MVP 国内场景用**高德**(已有账号、生态成熟),架构上将地图能力抽象为 provider 接口(地理编码/POI 搜索/路径规划/静态图),ADR 记录选型与备选(腾讯);二期出境游场景再评估 Mapbox(主力)+ OSM(兜底),坐标系转换(GCJ-02↔WGS-84)在 provider 层处理。

**决议(2026-10-21)**:用户确认,按建议执行。已落实:MVP 地图用高德(§6 已有);M1 待办:地图 provider 接口抽象 + POI 搜索缓存方案写入架构设计,选型与备选(腾讯/Mapbox)记入 ADR。

### RP-4:国外地图 Mapbox vs Google Maps——免费调试用哪个?中国大陆个人开发者接入门槛?

- **提出**:2026-10-21,用户
- **状态**:✅ 已决议(2026-10-21 用户确认)

**调研结论(全网调研,2026-10-21)**:

1. **免费额度对比(2025-03 Google 改制后)**:
   - **Mapbox**:每月免费 **5 万次地图加载 + 10 万次地理编码 + 10 万次路径规划**,注册不需绑卡
   - **Google Maps Platform**:取消原 $200/月通用额度,改为按 SKU 免费——Essentials 类 1 万次/月、Pro 类 5,000 次/月、Enterprise 类 1,000 次/月(2D 瓦片 10 万次/月);**必须开通计费账户(绑国际信用卡)才有免费额度**
2. **超量单价**:Google 地图加载 $7/千次、地理编码 $5/千次;Mapbox 约 $0.5/千次加载、$0.75/千次地理编码——Google 贵一个数量级
3. **中国大陆接入门槛**:
   - **Google**:需 Google Cloud 计费账户 + 支持国际支付的 Visa/Mastercard(国内卡常被拒,账单地址有讲究);且 Google 地图瓦片服务在大陆网络**不可直连**,本地调试需全程代理,体验差
   - **Mapbox**:邮箱注册即可,免费档**不绑卡**;api.mapbox.com 大陆可直连(偶有波动但可用)
4. **数据质量**:海外 POI 与路径数据 Google 最优,Mapbox 次之(基于 OSM+商业数据);免费调试阶段两者都够用

**建议**:免费调试 + 中国大陆个人开发者场景选 **Mapbox**(免费额度大 5-10 倍、不绑卡、大陆可直连);Google Maps 仅在未来对数据质量有强需求且解决支付/网络问题后再评估。此结论仅适用于**国外场景**;国内场景维持 RP-3 决议(高德)。

**决议(2026-10-21)**:用户确认,按建议执行。国外场景地图选型定为 Mapbox(免费调试)+ OSM(兜底),列入 M1 地图 provider 接口设计与 ADR;Google Maps 暂不接入。

### RP-5:内容数据源——小红书/美团/大众点评能否接入?搜索工具能否替代?小红书会话采集是否可行?

- **提出**:2026-10-22,用户
- **状态**:✅ 已决议(2026-10-22 用户确认)

**调研结论(全网调研,2026-10-22)**:

1. **三平台均无合规的第三方数据 API**:
   - **小红书**:无公开内容搜索 API;第三方数据服务(新红/蝉妈妈)是付费营销工具;爬虫/抓包违反平台协议并撞《个人信息保护法》
   - **大众点评**:已并入美团体系,无独立开放 API
   - **美团开放平台**:支持个人开发者实名认证后免费接入 MCP/Skills,但开放能力面向**商家经营**(排队/预订/核销/外卖账号管理),不提供消费者侧"按目的地搜餐厅+评分"能力
2. **通用搜索工具可覆盖口碑内容,但覆盖不到小红书**:博查(中文,有官方 MCP 与 LangChain 插件)、Exa/Tavily(国际,有官方托管 MCP,均有免费额度)等可检索马蜂窝/携程攻略/知乎/B站/TripAdvisor/Yelp 等可索引内容;小红书内容封闭,搜索引擎同样收录极少——**任何合规渠道都拿不到小红书数据**
3. **实测验证(2026-10-22,OpenCLI 复用用户已登录的 Chrome 会话)**:
   - 开发期人工采集**可行**:搜索稳定;笔记正文可读(须用 explore/ 格式 URL,search_result/ 格式会被拒;偶发失败加 --trace 重试;操作间隔 2-3 秒防风控)
   - 样本质量高:新疆 30 天攻略(南北疆环线/公共交通可行性/住宿淡旺季价差/真实总花费约 1 万)、乌鲁木齐 17 家餐厅清单(6222 赞)
   - 局限:图文笔记正文在图片中,文字仅有 caption,信息损耗大;店名无地址坐标,需 POI API 补齐
4. **运行时接入不可行**:登录会话会过期、触发验证码,单账号承载不了多用户并发,且违反平台协议与项目安全红线(PII)

**决议(2026-10-22)**:用户确认。

1. 运行时内容数据走**双链路**:搜索 API(国内博查/国际 Exa/Tavily)取口碑内容 → LLM 提炼候选 → POI API(高德/Google Places)补齐地址/坐标/人均消费
2. **小红书半自动知识库**作为**餐饮推荐、旅行攻略、交通出行、酒店推荐、景点推荐**的参考内容源之一:开发期 OpenCLI 采集热门目的地高赞笔记 → LLM 提炼结构化条目 → 人工审核入库;产品运行时只读知识库,不实时访问小红书;知识库按季度重采保鲜
3. 运行时爬虫/会话采集方案明确排除
4. M1 待办:搜索 API + POI API 双链路接入方案、知识库存储格式与更新流程写入数据源 ADR;Google Places 与 RP-4(绑卡门槛)的衔接需在 M1 核实,必要时国外 POI 数据降级为 Foursquare

### RP-6:酒店数据源——实时价格/库存能否拿到?RollingGo 酒店 MCP 是否可行?

- **状态**:✅ 已决议(2026-10-22 用户确认,实测通过后采纳)

**调研结论(全网调研,2026-10-22)**:

   - **RollingGo 酒店 MCP**(道旅 DIDA,[官方 MCP](https://github.com/RollingGo-AI/RollingGo-hotel-MCP-CN)):全球 200 万+ 酒店实时库存,个人开发者申领 API Key 即用,当前阶段免费;返回酒店名/星级/实时价格/地址/坐标/设施/预订链接
   - **LiteAPI**(Nuitée Connect):300 万+ 酒店,核心查询/预订端点免费(合理 look-to-book 比例内),sandbox 自助接入 → 国际备选
   - **Amadeus Hotel API**:测试环境免费,国际覆盖 → 三线备选
   - Expedia Rapid / Booking 联盟:需企业资质或人工审核 → 排除

**实测验证(2026-10-22,mcporter 直连 mcp.rollinggo.ai)**:✅ 可行

| 测试项 | 结果 |
|---|---|
| 国内搜索(乌鲁木齐,2 大 1 小住 3 晚) | 真实酒店列表 + 实时价格(84-120 CNY/晚)+ 经纬度 + 设施标签 + 预订链接 |
| 房型级查价 getHotelDetail | 同房型多价格计划(98 元不可取消 vs 101 元可取消)、含早/无早、面积/楼层/有无窗 |
| 国际覆盖(京都) | 5 家酒店,3-3.5 星,651-1228 CNY/晚,坐标齐全 |

已知问题:searchHotels 的 nights 参数疑似未生效(预订链接显示 1 晚),M1 接入时需核对参数名;单次调用延迟数秒,需配合缓存控制 90 秒生成预算。

**决议(2026-10-22)**:用户确认,按建议执行。RollingGo 酒店 MCP 定为酒店实时数据源(只查询不预订,边界同 RP-1),酒店价格由区间估算升级为实时查询;新增 AC-12、§6 酒店数据源行;Q9 决议相应修订(酒店部分);降级链:RollingGo 不可用 → LLM 区间估算 + AC-10 标注。M1 待办:RollingGo 接入(含参数核对、延迟与缓存设计)+ LiteAPI/Amadeus 备选写入数据源 ADR。

**补充(2026-10-22,机票能力核实)**:RollingGo 另有机票 MCP(`searchAirports`/`searchFlights`,与酒店**共用同一 API Key**,仅 URL 不同 `/mcp` vs `/mcp/flight`),但据[官方文档(2026-08-12)](https://rollinggo.store/docs/mcp-docs/quick-start)**机票业务已下线维护**,实测两个域名均返回 404。机票/火车票实时查询维持 RP-1 飞常准方案;RollingGo 机票若恢复上线,可作为备选评估。
